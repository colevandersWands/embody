# Embody Examples

**A comprehensive collection of JavaScript examples designed to showcase execution tracing for educational analysis.**

This directory contains a carefully curated menagerie of examples organized by pedagogical progression and educational use cases. Each example is crafted to demonstrate specific aspects of JavaScript execution that are crucial for learning and understanding code behavior.

## Philosophy

These examples follow the **Study Lenses** educational framework, where different analytical perspectives reveal different insights. The execution traces generated by `embody` provide the raw data that educational tools can interpret to:

- Identify variable roles (counter, accumulator, flag, etc.)
- Track control flow patterns and iterations  
- Analyze scope and closure behavior
- Understand asynchronous execution timing
- Detect common misconceptions and errors

Examples are organized in **pedagogical order** - each section builds on concepts from previous sections:

## Misconceptions Integration

Each directory includes a `misconceptions/` subdirectory containing examples of **common student errors** for that topic. Misconceptions are treated as a **cross-cutting concern** rather than an afterthought - they appear wherever they're relevant to learning.

## Example Structure

Each example typically includes:

- **Essence file** (`*-essence.js`) - Minimal concept demonstration (25-30 lines)
- **Overview file** (`.js`) - Educational context pointing to essence + additional examples
- **README.md** - Educational context and trace analysis questions  
- **Misconception examples** - Common errors students make with this concept
- **Expected trace insights** - What the tracer should reveal about execution

## WWED Pattern: What Would Evan Do?

All examples follow the **WWED methodology** for educational clarity and focus:

### Core Philosophy
**Distill complex concepts to their irreducible essence.** Remove everything non-essential to understanding the core concept, then build up complexity only as needed.

### Two-File Pattern
1. **`concept-essence.js`** (25-30 lines)
   - Minimal demonstration of the core concept
   - No extra features, edge cases, or comprehensive coverage
   - Focus on the "aha moment" that makes the concept click
   - Clean, readable, immediately understandable

2. **`concept.js`** (30-45 lines)  
   - Overview pointing to the essence file
   - Additional context and examples
   - References to related concepts
   - Maintains educational progression

### Educational Benefits
- **Reduced cognitive load**: Learners aren't overwhelmed by comprehensive examples
- **Clear concept boundaries**: Each file has a single, focused learning objective
- **Progressive complexity**: Start with essence, build understanding incrementally
- **Better retention**: Minimal examples are easier to remember and apply

### Implementation Statistics
- **43 essence files** created across all concept areas
- **All 100+ line violations eliminated** through systematic application
- **Maximum 30-line limit** enforced for educational effectiveness
- **Systematic approach** to concept complexity management

## Usage with Embody

```javascript
// Trace any example
const trace = embody(exampleCode, {
  preset: 'detailed',
  variables: true,
  functions: true,
  controlFlow: true
});

// - Control flow patterns

```

## Contributing

When adding examples:

- **Follow the WWED methodology**: Create essence file first, then overview
- **Enforce 30-line maximum**: If longer, split into focused concepts
- **Follow the pedagogical progression**: Build on previous concepts only
- **Include relevant misconceptions**: Address common student errors
- **Provide clear educational context**: Explain the "why" not just the "how"
- **Focus on concepts that benefit from execution tracing**: Rich data for analysis
- **Test with `embody`**: Ensure examples generate meaningful trace insights

### WWED Guidelines for Contributors
1. **Start with essence**: What's the smallest example that demonstrates the concept?
2. **Question every line**: Is this essential to understanding the core concept?
3. **Single concept per file**: If explaining two concepts, create two files
4. **Progressive revelation**: Simple first, complexity later
5. **Cross-reference thoughtfully**: Point to essence files from overviews
